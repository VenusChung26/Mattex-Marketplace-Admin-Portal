# Domain 文件

本專案使用 **single-context**：根目錄 `GLOSSARY.md` 與 `docs/adr/`。

## 何時讀取

- 探索、設計、拆票或命名 domain 概念前，先讀根目錄 `GLOSSARY.md`。其中提及的既有交易詞彙可再查 `CONTEXT.md`。
- 處理某範圍前，讀取 `docs/adr/` 中相關決定；設計或票的內容與 ADR 衝突時，明確指出衝突及需要重議的原因。
- 若未來存在根目錄 `GLOSSARY-MAP.md`，依其指標讀取相關 context 的詞彙表與 ADR。
- 文件不存在時繼續工作，不先建立空檔。用語或取捨真正定案時，由 domain-modeling 補寫。

## 使用規則

- 票標題、設計建議、假設及測試命名，使用詞彙表的名稱，避免列在 `_Avoid_` 的同義詞。
- 詞彙表只記錄 domain 名詞定義；商業驗收規則與實作計畫放在對應規格及工作票。
- 文件對目前功能的描述與程式不一致時，先指出差異，不將舊描述直接當成新的業務限制。
- 沿用既有 ADR；新的 ADR 只記錄有實際取捨、難以逆轉且未來需要原因的決定。
