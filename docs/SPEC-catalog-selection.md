# 買家商品目錄與商品選擇一致性

## 商業目標

買家第一次開頁與載入完成後看到一致的商品及規格；選定需求後，刷新、草稿、詢價及文件不會無聲改成另一個選擇。減少重填、錯規格詢價及銷售人手核對。

## 已確認決定（2026-11-07）

1. **沿用商品呈現。** 沿用目前買家頁的商品分類、尺寸／規格合併及上下架規則。此輪集中結果一致性。
2. **有效資料保留，失效選擇重選。** 商品資料更新後保留仍有效的選擇及已填資料；標示失效選擇及受影響的相依選項，買家重選後才可提交。不自動以另一個尺寸或規格取代買家已選內容。
3. **不同商品選擇分行。** 同款商品的不同尺寸或規格分開保存，每行有自己的數量；草稿、詢價、採購單及文件均保持區分。
4. **增加採購量須買家確認。** 最低購買量提高、原有數量不足時，保留原數量並提示不足；買家確認調整數量後才可提交，不自動增購。
5. **無法核對時保留草稿並重試。** 提交時無法取得最新商品資料，暫停提交並提示重試；恢復連線後重新核對，不以未確認的選擇建立新記錄。

## 商業驗收情境

| 情境 | 預期結果 |
| --- | --- |
| 同一份商品資料供買家首次開頁及後續載入使用 | 商品集合、合併選項及分類一致。 |
| 商品更新，但買家已選尺寸與規格仍有效 | 保留原選擇及其他有效資料。 |
| 買家已選 80mm；更新後只提供 100mm | 清楚標示 80mm 已失效，讓買家重選；不自動轉為 100mm，不接受未修正的提交。 |
| 已加入草稿的規格失效 | 草稿保留其他有效資料，提示重選；檢查涵蓋真正提交的路徑。 |
| 原選擇失效，另一個無關規格仍有效 | 保留有效規格、數量及聯絡資料；只要求修正失效或受相依關係影響的選擇。 |
| 同款商品先選 80mm × 2件，再選 100mm × 3件 | 保留兩行及各自數量，不變成 100mm × 5件。 |
| 原選 10件，最低購買量更新為 20件 | 仍顯示原來的 10件並提示不足；買家確認改為合規數量後才可提交。 |
| 提交前無法取得最新商品資料 | 不建立新詢價／採購單，不清空草稿，提示買家重試。 |
| 連線恢復，買家重試 | 重新核對最新商品及選擇；通過後才提交。 |
| 已修正選擇並提交詢價 | 銷售收到的規格與買家確認的選擇一致，文件沿用該選擇。 |
| 已標價現貨以不同規格建立採購單 | 伺服器保存的明細及買家文件，均保留各行選擇與數量。 |

## 落實上述決定的驗收要求

- 規格失效的檢查涵蓋商品卡、列表、詳情頁、登入前後的待處理選擇、草稿，以及詢價／即買採購單的最終提交。
- 伺服器亦須核對最新商品選擇；只停用畫面按鈕不足以通過驗收。
- 分行後，數量修改、移除及提交的對象均須是該行的商品選擇，不能連帶修改同款商品的另一個規格。
- 同一商品及同一組尺寸／規格再次加入時，可沿用目前累加數量的行為；不得跨規格累加。
- 首次開頁的現有預設選項，與買家已選內容在更新後失效，是兩種情境；後者必須要求重選。
- 已提交的選擇與數量作為文件依據，避免日後下載文件時按當前商品目錄重新解讀成另一個選擇。
- 訂製需求保留自由描述、尺寸及附件的既有流程；不以標準商品選項是否存在來否決訂製詢價。
- 遵守 ADR-0001：詢價狀態、編號及時間由伺服器決定，提交失敗時瀏覽器不自行建立成功結果。

## 實作前背景

- 買家頁與 SSR 目前使用不同的商品整理流程：`api/catalog-snapshot.js`、`src/lib/ssrCatalog.js`、`server/public-catalog.js`。
- `SpecGroupPicker` 現有相依選項同步會選取首個可用選項，需要區分首次預設與更新後失效。
- 草稿目前按商品 ID 合併，未區分尺寸／規格組合。
- 商品選擇已保存在詢價完整快照，但標準提交明細未完整表達選擇；現有提交前檢查主要針對商品是否下架，尚需核對規格組合。
- 即買採購單目前只傳送商品 ID 及數量；須將伺服器記錄、畫面及文件的商品選擇統一。
- 文件目前有從當前商品目錄解析規格標籤的路徑，須區分已提交快照與尚未提交的選擇。

## 推進次序

1. **買家商品目錄 module：** 集中既有買家可見性、規格合併次序、分類及版本識別，先驗證首次開頁與後續載入的一致性。
2. **商品選擇 module：** 集中選擇有效性與相依規則，再貫通展示、登入、草稿分行、最終提交及文件。
3. **按商業情境驗收：** 透過實際 caller 使用的 interface，驗證正常選購、目錄變動、數量不足及連線失敗；保留既有規則測試，補上跨流程測試。

商業決策已定案，8 張票的實作與驗收記錄見 `.scratch/catalog-selection/issues/`。商品選擇共用規則位於 `src/lib/productSelection.js`，伺服器提交邊界位於 `server/verify-selections.js`；買家目錄共用投影位於 `server/public-catalog.js`。
